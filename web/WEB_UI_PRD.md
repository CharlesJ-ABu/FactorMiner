# FactorMiner Web UI 功能与交互规格

[English](WEB_UI_PRD.en.md)

更新于 2026-11-25。当前发布范围是源码 checkout 中的本机单用户研究工作台。本文区分已实现、部分实现和规划；安装见[产品指南](../docs/FactorMiner_Product_Report_ZH.md)和[前端说明](README.md)。

## 模块一：Dashboard 与 Launchpad

### 1. 全局指挥中心（已实现）

首页 `/` 读取实际 API/档案，展示引擎在线状态、任务统计、因子库存、Miner 与生命周期分布、高分候选及最近 6 个任务。因子入口进入 Inspector；任务入口进入 Launchpad 列表后再打开详情。API 重启清空任务历史，因子档案继续保留。

### 2. 配置与发射（已实现）

Launchpad 从工作区读取 Miner 和 JSON 配置，展示交易对、周期、迭代等摘要；参数修改仍需编辑文件。POST `/api/launch` 返回任务 ID，后台经 `asyncio.to_thread` 执行数据读取、初始化和挖掘。启动校验失败显示原因，排队响应不代表执行成功。

### 3. 任务追踪（已实现）

- 每次挖掘有独立任务行，点击打开居中模态详情，显示状态、配置、错误、结果与日志。
- WebSocket 按 task ID 逐事件更新任务、日志和散点；迟到 HTTP 快照不覆盖已收到的实时状态，终态不退回旧进度。
- 连接恢复重放当前 API 进程的最新任务状态；服务重启不恢复任务历史，没有微秒级延迟保证。

## 模块二：挖掘监控

### 1. IC 与复杂度散点（已实现）

X 轴为 Epoch，Y 轴为每轮最佳候选 IC；提示框显示实际复杂度，颜色按复杂度映射。它不代表整轮全种群、谱系分支、Sharpe 或交易收益。正/负 IC 都需结合因子方向解释，不把图上高点称为“高收益区”。

### 2. LLM 反思展示（部分实现）

通用 Execution Console 显示任务日志，Inspector 展示已存源码和反思记录。专属实时侧栏/抽屉仍是规划；捕获错误并改写代码不证明因果性、逻辑正确或样本外有效。

## 模块三：Factor Inspector

### 1. 异构逻辑展示

- **GP（已实现基础树图）**：ECharts AST tree 支持展开/收起、节点提示与表达式文本；局部表达式高亮解释器仍是规划。
- **LLM/RL（已实现档案展示）**：源码、反思或已存动作轨迹；参考 RL 的可计算公式按 AST 展示。
- **NN（部分实现）**：模型版本、通道、工件状态；隐空间三维散点和特征重要性图尚未实现。
- 对外使用 NN；后端兼容归一化旧 `dl_channel` 档案。

### 2. 快照诊断（已实现）

从已存 factor/forward-return 快照计算滚动 IC、分组平均未来收益和因子差分换手；支持比较 2–5 个有快照的因子。没有快照时提示不可用，不生成演示曲线。这些图不是含交易成本的策略净值。

### 3. 高级图表与交互（规划）

净值/最大回撤、多空策略收益、衰减热力图尚未实现。现有图表提供轴提示；框选缩放和跨图十字光标联动也仍是规划。

## 模块四：生命周期与执行边界

### 1. 生命周期管理（已实现）

详情页显示 `DISCOVERED / INSPECTED / PAPER_TRADING / LIVE / RETIRED`，支持单个和批量变更。它们都是人工标签，修改不会启动模拟盘或实盘。

### 2. 编译与实盘上架（规划）

当前 FactorCompiler 只把可恢复档案重建为本地 Python callable；没有 C++ 编译、远端推送或交易网关，Web 也没有部署按钮。后续若接入交易系统，只有真实执行端确认后才能展示部署成功；现有生命周期标签不能作为确认。

## 模块五：Data Center

### 1. 元数据（已实现基本路径）

切换 Binance/OKX 或市场类型时，通过 `/api/exchange_meta` 获取 USDT 标的和周期；可用时按 24h quoteVolume 排序，最多返回 200 个标的。网络失败可回退静态名单，名单存在不证明交易所可达或标的一定受支持。

### 2. 批量选择与覆盖表（已实现）

Symbols、Timeframes 多选，Trade Type 单选；API 接受市场数组，但当前 UI 不提供市场多选。选择变化后延迟查询各组合，宽表显示文件存在性、起止时间和行数，不将时间范围作为逐根完整性证明。

### 3. 下载与终态（已实现）

支持 merge、fill_gap、overwrite。一批组合在后台顺序执行，独立任务可以并行；WebSocket 负责状态通知，不是下载调度器。控制台显示进度、补缺和错误摘要，不保证逐根 K 线的完整日志。

任务采用唯一 ID，终态为 `completed / failed / partial_failed`；100% 仅表示处理比例，失败/部分失败不显示成功。提交期间缓存当前任务事件，终态不被迟到进度覆盖。监控断线提示连接中断，不自行判失败；重连可恢复内存中的最新状态，后端重启不恢复。

## 发布与验证范围

Python ≥3.10（已实测 3.12），Node.js ≥22.12。源码安装 `pip install -e '.[test]'`；前端使用 `npm ci`、`npm test`、`npm run build`。默认前端连接本机 8000，开发页为 5173，没有完整认证/多租户体系。

中/英/德切换已覆盖导航、Dashboard 和 Inspector，部分页面与日志保留原语言。组件/hook 的受控事件测试不等于真实浏览器网络、跨进程恢复、远程部署或交易收益验收。
