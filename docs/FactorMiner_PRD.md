# FactorMiner 产品需求文档 (PRD)

## 1. 产品概述
**产品名称**: FactorMiner
**当前版本**: V4.0.0，更新于 2026-11-25。
**产品定位**: 从源码 checkout 运行的本机单用户因子研究工作台，提供多范式候选生成、评估、存档和 React/Vite 审查界面。当前不包含交易账户、订单执行或完整组合回测系统。
**目标用户**: 量化交易者、金融数据分析师、量化策略研究员。

本文标注当前实现与规划。安装和首次使用以[产品指南](FactorMiner_Product_Report_ZH.md)为准；“规划”不构成当前版本承诺。

## 2. 核心业务流程
1. **数据获取与管理**: 从交易所下载高质量K线数据，支持高级动态元数据联动获取（按流动性排序）、智能批量下载与前端控制台实时监控、覆盖率检查和断层修复。
2. **因子挖掘**: 支持四大异构流派 (GP、RL、NN、LLM) 统一调度与生成。
3. **因子存储**: 标准化存储与谱系追踪，分离灵魂（逻辑代码/模型权重）与肉体（Parquet截面得分矩阵）。
4. **因子评估（已实现）**: 并行计算 IC、RankIC、因子值变化与自定义 fitness；默认基于源码哈希去重。Inspector 提供相关性诊断，不计算交易账户胜率。
5. **因子优化与组合（规划）**: 单因子选择已存在；统一多因子组合优化尚无产品入口。

## 3. 功能需求详细说明

### 3.1 数据管理模块
- **数据源获取**: 深度集成 CCXT 框架，动态读取各交易所元数据与流动性排序。支持多时间框架 (1m, 5m, 15m, 1h, 4h, 1d)。
- **批量与智能下载**: 支持基于“Exchange -> TradeType -> Symbol”级联过滤的多维度笛卡尔积批量下载，彻底解决错乱文件命名的问题 (`1000CAT_USDT_USDT-1m-futures`)。
- **数据质量控制**:
  - Web 宽表展示本地文件是否存在、起止时间和记录数；这不等同于区间无缺口或因子 Coverage。
  - 自动断层检测与智能填充 (Gap Filling) 以及增量（Merge）下载更新功能。

### 3.2 因子挖掘与计算模块 (V4)
- **GP（已实现参考搜索）**: 生成 AST、变异和精英保留；完整交叉策略属于扩展方向。
- **RL（部分实现）**: `MyCustomRL` 按评分更新算子/字段采样权重；内置 `RL` 是随机动作演示骨架，尚非完整 Actor-Critic、PPO 或 DQN。
- **LLM (大语言模型)**: 基于 In-context 动态生成与执行沙盒反馈（Reflection），驱动安全迭代。
- **NN（已实现参考模型）**: 默认 NumPy MLP 在训练段拟合模型和标准化参数，再筛选并保存输出通道。训练分支的 `requires_grad` 标志不是通用 PyTorch autograd 图保证；用户可扩展模型协议。test_period 参与通道选择时是验证集，不是未见最终测试集。

> 命名约定：历史名称 `DL` 已弃用，对外产品、配置和界面统一使用 `NN`；旧档案仅做兼容读取。

### 3.3 因子评估体系
- **并发与去重（已实现）**: 本地评估线程默认 8，可配置 1–64；`DiversityFilter` 使用源码 MD5，不能识别所有语义等价因子，也不是通用 Anti-Bloat 限制。参考 NN 另有输出相关性筛选。
- **防御性沙箱（已实现有限边界）**: AST/API 白名单、独立进程和资源预算约束代码执行；不替代因果性、前视偏差或研究有效性审查，平台资源限制依赖操作系统支持。
- **分布式执行（规划）**: 未接入 Ray/Celery 后端。

### 3.4 因子优化与组合（规划，尚未交付统一入口）
- **优化算法**: 贪婪算法、遗传算法、Lasso回归，控制过拟合并最大化IC。
- **组合方式**: 等权重、IC加权、机器学习加权。

### 3.5 谱系感知因子存储架构 (V4)
- **元数据绑定（已实现）**: `FactorMetadata` 保存逻辑、指标、数据血缘、创建时间、选定配置字段及 Miner 声明的父代引用。父引用未必能解析为已入库 Factor ID，不等于完整演化图或搜索状态恢复。
- **异构存储（已实现主要路径）**: GP/参考 RL 保存可计算 AST；LLM 保存源码、反思与模型来源；NN 保存可移植模型和通道。旧 action-only RL 档案不能据此恢复可执行因子，策略网络完整 checkpoint 尚未贯通。

### 3.6 用户界面与交互接口 (Web UI & CLI)
- **指挥中心 Dashboard**: React/Vite 构建。提供一键任务发射、动态配置加载、以及全局挖掘指标看板。
- **监控大厅与控制台（已实现）**: WebSocket 推送任务、日志与每轮最佳候选 IC/实际复杂度；模态详情展示结果。没有微秒级延迟保证；反思通过通用日志/存档展示，专属实时抽屉未实现。状态只存当前 API 进程内，重连重放，重启不恢复。
- **命令行界面 (CLI)**: 纯无头模式运行，支持 `factorminer mine`（配置驱动挖掘）、`factorminer download`（行情批量下载）和 `factorminer inspect`（因子多维审查与归因）。
- **API 接口（已实现）**: FastAPI 与计算线程分离；发布默认仅监听本机，无完整认证或多租户体系。

### 3.7 因子归因与审查引擎 (Factor Inspector)
- **相关性诊断（已实现）**: Pearson IC、Spearman RankIC、IR、t-stat 与正 IC 比例。IR 当前固定乘 `sqrt(252)`，未按 K 线周期/交易日历校准；不作为任意周期的年化收益或交易胜率。
- **Coverage（已实现，口径需区分）**: CLI Inspector 以因子/标签共同有效观测计算；跨资产以矩阵单元为分母。默认挖掘评分的输出覆盖、Data Center 的文件范围是不同指标，详见[评分指南](fitness_hook_guideline.md)。
- **Lag 衰减（已实现）**: 默认 Lag 1、2、3、5、10，各请求段独立构造标签。
- **分组诊断（部分实现）**: 单标的 5-Quantile 平均未来收益与 Q5−Q1；缺组为不可用。底层跨资产 CLI 分组收益尚未实现；Web 另用已存快照计算分组。因子差分换手不等于账户成交量。
- **输入与失败（已实现）**: Factor ID、合法 AST 或 Python 因子代码；失败逐标的显示原因，任一失败 CLI 非零退出。跨资产 NN 的 CLI 复评明确拒绝；完整矩阵可通过 Python Resolver 使用。
- **Web 快照审查（已实现）**: AST 树、源码/反思、模型/通道信息、滚动 IC、分组与换手、2–5 因子比较、生命周期人工标记。NN 三维/特征重要性、净值/回撤和交易部署界面属于规划。

## 4. 系统架构设计 (V4)
- **展现层**: React.js, WebSockets, ECharts 可视化 (独立运行在 5173 端口)。
- **控制层**: FastAPI（本机 8000 端口），BackgroundTasks 调用 `asyncio.to_thread` 执行同步数据/挖掘工作；任务状态在进程内存。
- **抽象层**: 引入 `BaseFactorMiner`, `FactorExpression` 统一范式。
- **审查与归因层**: 引入 `core/inspector` (`FactorResolver`, `InspectorMetricEngine`, `InspectorReporter`, `FactorInspectorEngine`)。
- **底层引擎**: 异构存储引擎、并发评价引擎池、自动数据补全探针。

## 5. 当前阶段与重点迭代方向 (V4 落地与扩展)
- **完善多资产跨截面挖掘**: 强化 `cross_asset` (横截面运算) 原生能力。
- **MCP协议改造 (Model Context Protocol)** (规划中):
  - **目标**: 将核心服务转化为MCP标准服务，赋能AI大模型与Agent直接调用。
  - **接口规划**: `get_market_data`, `compute_factor`, `evaluate_factor`, `mine_factors`, `inspect_factor`等。

## 6. 非功能性需求
- **环境要求**: Python ≥3.10（已实测 3.12）、Node.js ≥22.12；内存/磁盘随数据和模型规模变化，不提供未经测量的固定容量保证。源码安装 `pip install -e '.[test]'`；前端使用 `npm ci`、`npm test`、`npm run build`。
- **可用性**: 提供良好的错误处理、日志记录与Web端实时进度反馈。
- **扩展性**: 系统需保持模块化设计，以支持未来轻松接入更多数据源、因子类型与评估算法。
